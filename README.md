# ラテ混合 SNS 実験刺激

外部ライブラリ・画像・フォント・通信APIを使わない、HTML / CSS / JavaScript のプロトタイプ。架空アカウント `nagi_coffee` の同一投稿で入力源を切り替えます。ブランド名の商標調査は行っていません。

公開プレビュー：[Passive](https://mlabpages.github.io/latte-agency-stimulus/?condition=passive) / [Interactive](https://mlabpages.github.io/latte-agency-stimulus/?condition=interactive)。このプレビューはログを外部保存しません。

## 起動

このフォルダで `npm start` または `node server.js`。表示された localhost のURLを開いてください（ポートは自動選択）。HTMLの直接ダブルクリックはES Modulesの制限があるため使用しません。

- `/?condition=passive`：自動混合
- `/?condition=interactive`：グラス上で円を描くドラッグ
- パラメータ省略：設定の既定条件。不正値：エラー画面（参加者を別条件に黙って割り付けません）。

同じ静的ファイルを任意のHTTPSホストに配置できます。ローカルサーバーはPC内の確認用で、スマホ実機からは接続できません。実機検証にはHTTPS環境を使ってください。

## 構成と変更箇所

| ファイル | 役割 |
| --- | --- |
| `config.js` | 文言、色、時間、必要回転数、入力範囲、条件、遷移先を一括設定 |
| `index.html`, `styles.css` | 共通のSNS投稿レイアウト |
| `mixer.js` | 自動再生量、角度差、混合率の純粋関数 |
| `renderer.js` | 条件に依存しないCanvas描画。商品・背景の差し替え境界 |
| `app.js` | 条件切替、Pointer Events、提示時間、完了処理 |
| `logger.js` | 独立したログ生成・スナップショット・通知関数 |
| `server.js` | 依存不要のローカル確認サーバー |
| `tests/mixer.test.js` | 角度境界・クリック・混合率の検証 |

商品を写真に変更する場合も、両条件が同じ `renderer.draw(progress, angle)` を使う設計を維持してください。初版は一枚の画像への差し替え設定ではなく、Canvasのグラス／液体／氷／スプーンを別々に描画しています。混合可能な写真表現には背景・グラス・液体・スプーンのレイヤー素材が必要です。

## 動作と統制

1. 同じCanvas・同じ初期角度・同じミルク／コーヒー色から開始。
2. Passiveは静止700ms後、5,500msで4回転。Interactiveは実際の角度差をそのまま共通のスプーン軌道に反映。クリック・単なる長押しでは混ざりません。指を止めると描画状態も止まります。
3. 累積した有効な角度移動が4回転分で混合完了。時計回り・反時計回りとも対応します。往復も角度移動量に含むため、`approximateTurns` は厳密な円の完成回数ではありません。直線を横断するだけでは中心の無効領域／大角度ジャンプの除外により進みにくい設計ですが、円運動の形状を厳格に認定するアルゴリズムではありません。
4. 混合完了時は共通の均一色・スプーン静止位置に揃えます。逆回転や往復後には終端のスプーン位置が小さく切り替わる場合があります。液体表現は物理シミュレーションではなく層の境界と色の補間です。
5. 混合完了かつ提示6,200ms経過で「次へ」。早く混ぜた場合は最終状態を保持。30秒未完了なら未混合のまま救済の「次へ」を表示し、未完了として記録します。
6. タブ非表示中は提示時間・自動再生・フォールバック時計を停止し、操作を解除。復帰後に再開します。非表示の事実はログに残します。OS固有の省電力によるフレーム低下は検出・補正できません。

| 同一にしているもの | 条件間の差・限界 |
| --- | --- |
| 商品・背景・位置・色・氷・SNS UI・キャプション | 指示文の内容。領域サイズは共通 |
| 混合率と色・模様を対応させる描画関数 | 実際の指の速度／停止／反転による時系列 |
| スプーンの投影された円軌道 | 自動一定速度と参加者の連続入力 |
| 初期状態・混合成功時の最終状態 | 救済試行は未混合のまま終了 |
| 最低提示時間6.2秒 | 操作の遅いInteractiveは延長（最大30秒） |

## ログと連携

DevToolsで `window.latteExperiment.getLog()`。`console.log` は開始・混合完了・提示終了・次へ・離脱時に出力します。値はページ内メモリだけにあり、更新・閉じると失われます。収集サーバーや永続保存は含みません。`completed` は十分混ざったかを意味し、「次へ」が表示されたか／押されたかとは別です。

```js
window.addEventListener('latte:next', ({ detail: log }) => {
  // Qualtrics等の親側で log を保存してから、次の設問へ進める。
  console.log(log);
});
window.addEventListener('latte:log', ({ detail }) => {
  // detail.type, detail.log を必要に応じて収集する。
});
```

`nextUrl` が空なら完了メッセージを表示し、`latte:next` を発行します。URLを設定すれば遷移しますが、遷移前の保存は連携側の責任です。iframe越しの連携は別途実装が必要で、親ページが直接このイベントを受け取ることはできません。Qualtrics本番への埋め込み・値の保存は未実装です。

| 主なフィールド | 定義 |
| --- | --- |
| `stimulusStartAt`, `stimulusEndAt` | UTC ISO時刻。初回描画から「次へ」解禁（または途中離脱）まで |
| `stimulusDurationMs` | 非表示時間を除く提示時間。「次へ」を押すまでの待ち時間は含めない |
| `operationStartAt`, `operationEndAt` | 初回の有効領域pointerdownと最後のpointerup／解除時刻 |
| `operationDurationMs` | 指を下ろしていた区間の合計。ドラッグ中の静止時間も含む。区間終了時に更新 |
| `operationSpanMs` | 最初の操作開始から最後の解除まで。操作間の休止も含む |
| `pointerDistancePx` | 捕捉中のpointerの移動距離（CSS px、画面サイズに依存） |
| `pointerDistanceScene` | 同じ距離を400×500の論理座標へ換算 |
| `approximateTurns` | 有効角度移動の絶対値合計 / 2π。操作の往復を含む |
| `timeToMixMs` | 刺激開始から混合完了までの表示時間。未完了はnull |
| `operationTimeToMixMs` | 操作開始から混合完了までの実経過時間。非表示や休止を含む |
| `completed`, `fallbackUsed`, `exitReason` | 混合成功／救済解禁／終了理由（completed, timeout, pagehide） |
| `hiddenDurationMs`, `visibilityChanges`, `interrupted` | タブ非表示・中断の情報 |
| `settings`, `stimulusVersion`, `pointerType` | 再現用設定、バージョン、最後の入力種別 |

Passiveの操作関係の時刻・距離・回数はnull／0。未操作のまま救済したInteractiveも同様です。途中で閉じた際のログ通知はbest effortであり、送信保証はありません。参加者IDは扱いません。

## 実験上のレビュー

この実装が操作するのは「参加者の継続入力と画面の連動の有無」です。sense of agency の主観的変化を保証するものではありません。随伴性を持つ中間過程もagency判断に関与しうることは [Caspar et al. (2016), The Sense of Agency as Tracking Control](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0163892) で扱われています。

以下はこの実装についての設計上の推測・検討事項です。

- Interactiveだけに運動負荷・注意配分・指による遮蔽・達成感が生じます。操作努力や楽しさ、操作の難しさを別に測り、agencyの操作チェックと区別してください。
- 提示時間を同一にするために勝手に自動混合すると随伴性を壊すため、初版は最低時間だけ固定しています。完全な時間統制が必要なら、予備実験で所要時間分布を測り、同じ操作系列を別参加者のPassiveへ再生するyoked設計を検討できます。この版はyoked再生や軌跡保存を実装していません。
- 2条件だけでは運動の有無とagencyの効果を切り分けきれません。運動量を揃える非随伴操作条件を追加するかは研究計画に合わせて判断してください。
- 救済試行は曝露時間・最終状態が異なります。事前に除外／別集計の方針を決め、`fallbackUsed`・中断ログ・実時間を残してください。
- 救済や操作チェック失敗は処置後の変数です。主解析から機械的に除外せず、割付ベースの主解析と、事前に定めた感度分析を区別してください。
- 標準自動軌道の速度と参加者の速度は同じとは限りません。滑らかさも端末フレームレートと入力頻度に依存します。
- スマホではグラス中央付近に半径約60〜80論理pxの円を描く想定。グラス外のスワイプはページスクロールできますが、刺激Canvas内はブラウザのスクロールを止めます。小画面ではページ下部が画面外になることがあります。
- 指示理解、片手操作、低性能端末、iPhone/Safari、実際の指の遮蔽・疲れは実機の予備実験が必要です。マウス・エミュレートしたタッチの確認は実機確認の代替ではありません。
- 視覚運動自体が刺激のためreduced-motionで運動を省略しません。設定の検出値をログに残すので参加可否・別対応は研究手続き側で決めてください。キーボード専用操作は初版の対象外です。

### 尺度と分析の位置づけ

agency・没入感は「条件によって変わる心理過程」の候補として、商品評価／購買意図などの主要アウトカムとは分けて測定する設計が考えられます。agencyは今回の画面変化に対する状態的な統制感、没入感はこの短い投稿への注意・吸収を対象にし、両概念を同じ尺度得点にまとめません。楽しさ・操作努力・難しさも代替説明の候補です。これは本刺激への設計提案で、尺度の妥当性を確認済みという意味ではありません。

主解析はランダム割付条件によるアウトカムの差。心理尺度は操作チェックと機序の探索／事前規定した媒介分析に用いる案が妥当です。刺激後に測るagency・没入感・努力・所要時間をすべて単純な共変量として投入しても、「agencyだけの因果効果」にはなりません。処置後変数への条件づけによるバイアスに注意が必要です（[Montgomery, Nyhan & Torres, 2018](https://doi.org/10.1111/ajps.12357)）。条件をランダム化しても媒介変数自体がランダム化されるわけではなく、媒介効果の因果解釈には追加の仮定が必要です。

一般的・特性的なagency信念を測る [Sense of Agency Scale](https://pmc.ncbi.nlm.nih.gov/articles/PMC5600914/) を、そのまま数秒のラテ操作に対する状態尺度として扱わないでください。没入感もpresence／flow／focused attentionのどれを対象にするかを先に決め、短い刺激に合う尺度・日本語版・使用条件を確認する必要があります。

## 検証

`npm test`：角度の±π境界、初回接触／大きな跳躍の無効化、標準自動再生の開始・中間・完了率を検証します。

ブラウザでは両条件の初期／最終Canvas一致、クリックで進まないこと、静止時に進まないこと、マウス回転、タッチPointer Events、救済時の未完了ログ、画面幅320／390／1280px、ログ取得、次へを確認します。実施結果と実機未検証の区別は作業完了報告を参照してください。
